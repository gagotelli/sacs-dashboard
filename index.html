Why there are no ticket subjects here

This dashboard is served from a public repository, and its sign-in is client-side only — anything stored here is readable by anyone. Helpdesk subjects routinely name students and staff, so this page shows what tickets are about (category, priority, status) and never who raised them. Use the ManageEngine link above for individual tickets, where real authentication applies.

The one exception is Workload by technician below, which names the IT staff a ticket is assigned to. That is team workload rather than anyone's personal data, but it is published to the same public repository, so it is called out here rather than left implied.

    Open SharePoint

    Why this needs setting up

    This dashboard is a static site — there is no server behind it. The SharePoint library is behind Entra ID sign-in, so the page cannot read it directly from your browser without exposing credentials in public JavaScript.

    The fix is the same pattern already used for Auvik, NinjaOne, Meraki and Arctic Wolf: a scheduled GitHub Action authenticates with Microsoft Graph, walks the library, and writes a plain data/sharepoint.js index of folders and file names. The dashboard renders that index. File contents are never copied — only names, paths, sizes and modified dates, with each entry linking back to SharePoint where real access control applies.
